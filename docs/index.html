Course design advice that shows its sources.

idstack reviews your course in Claude Code, Cowork or Chrome. What it does for you, and for your team.

You are the designer. idstack does the first draft, the review and the search for the research, and you make each decision.

For one designer

A second opinion in one minute
Paste an objective, a quiz question, a rubric or a slide. You get a maximum of five findings, each with its study, and a corrected version.
A first draft to start from
Objectives with Bloom's levels, rubrics, question banks, storyboards and module pages. You approve, change or remove each row.
An answer to "why?"
When a subject matter expert disagrees, you show the study and how strong its evidence is.
A full course audit in one afternoon
Import a course from your LMS. You get a quality score, an accessibility score and a list of what to correct first.

For a design team

One standard of review
Each course is examined against the same standards: Quality Matters, WCAG 2.1 AA and constructive alignment.
Reports that you can send
Each skill writes a plain Markdown report for faculty, clients and curriculum committees. Each finding has its evidence tier.
Design decisions stay with the course
The needs, the objectives and the alignment are saved in the course folder. A different designer continues where the first one stopped.
New designers learn the reasons
idstack explains each step and each term to a new designer, and it is brief with an expert.

Free and open source. idstack keeps the course files in a folder on your computer.

Sixteen skills, in the framework you already use.

Eight skills run in sequence through /idstack:pipeline. Three more handle first-run setup, course import and course memory. Four companion skills work at any time: feedback on one item, a storyboard, a question bank and an evaluation plan. You can run any skill alone, with no manifest.

Show the phases of

ADDIE evaluates two times. The three review skills are the formative evaluation, before the launch. /idstack:evaluation-plan plans the summative evaluation, after it.

Results first, then the evidence, then the lessons. The pipeline uses this sequence, so /idstack:course-builder writes no lesson before the objectives and the assessments are there.

Each skill can run again, and the course folder keeps your decisions. Storyboard one module as the prototype, review it with /idstack:quick-check, and start the next cycle.

Every recommendation cites its source.

The 11 research domains below are ranked by study count. Each bar shows the tier mix of that domain's references. You can see where idstack rests on trials and where it rests on reviews or expert opinion. When findings conflict, the stronger tier wins. All 154 references are in evidence/references.md. Every source is public, and you can check every citation.

T1 meta-analyses & RCTs T2 quasi-experimental with controls T3 systematic reviews T4 observational T5 expert opinion & theory

  1. Cognitive Load Theory & Instructional Sequencing

    19 studies

    Working memory holds only a few new ideas at one time. Cognitive load research shows when a visual cue helps, and when a repeated explanation overloads the learner. T1–T5

  2. Formative Assessment & Feedback

    19 studies

    Feedback that explains the error and the next step improves retention. Feedback that only marks an answer right or wrong does less. Nicol's principles give criteria for rubrics, self-assessment and peer review. T1–T5

  3. Instructional Design Models & Frameworks

    15 studies

    ADDIE, ARCS, ASSURE and UDL fit different contexts. A 2025 review [ID-7] [T3] compares the strengths and limits of ADDIE, ARCS, and ASSURE. It proposes a framework that combines them. T1–T5

  4. Evaluation Models

    15 studies

    Plan the evaluation while you design the course, not after it. Kirkpatrick's four levels measure reaction, learning, behavior and results. Satisfaction alone does not show learning. T1–T5

  5. Multimedia Learning Principles

    14 studies

    Mayer's principles (coherence, signaling, segmenting, modality, redundancy) tell how to combine words and pictures. Text or decoration that does not teach adds load and reduces learning. T1–T5

  6. Online Course Quality Frameworks

    14 studies

    Quality Matters (QM) standards and the Community of Inquiry (CoI) model are the most studied frameworks for online course quality. CoI measures teaching, social and cognitive presence. idstack audits against both. T1–T5

  7. Constructive Alignment & Learning Objectives

    13 studies

    When objectives, activities and assessments do not agree, students learn less. The revised Bloom's taxonomy classifies each objective, so that the assessment can measure the same level. T1–T5

  8. Accessibility & Universal Design for Learning

    13 studies

    WCAG 2.1 AA is the legal baseline for digital accessibility. Universal Design for Learning (UDL 3.0) plans three pathways (engagement, representation, and action) from the start, so that more learners can succeed. T1–T5

  9. Learner Analysis & Differentiation

    11 studies

    Prior knowledge is the strongest predictor of what a learner gains from instruction. Novices need support that slows experienced learners. This is the expertise-reversal effect. T1–T5

  10. Needs Analysis

    11 studies

    A needs analysis examines three levels (organization, task and learner) before anyone writes content. It keeps the course on the skill gap, and it shows when training is not the answer. T1–T3

  11. Rapid Prototyping & Design-Based Research

    10 studies

    A pilot with real learners finds usability and content problems early. Design-based research gives the revisions a method. T2–T5

Every recommendation has a research domain code and an evidence tier, for example [Alignment-14] [T1]. The code points to the paper in evidence/references.md.

Each pipeline skill writes a report and a manifest.

Each skill that produces findings writes two files: a Markdown report for faculty and stakeholders, and a JSON manifest that later skills read. Reports go in .idstack/exports/<course-slug>/. The manifest is .idstack/project.json.

Markdown · .idstack/exports/<course-slug>/learning-objectives.md

Finding align-1 warning T5

What we saw: 3 of 8 stated learning objectives have no associated assessment items.

Why it matters: In constructive alignment, each objective has an assessment that measures it, so learners and teachers can see what the course asks for. [Alignment-1] T5

Recommendation: idstack recommends that you run /idstack:assessment-design to add aligned assessments, or change the objective list.

The report is plain text that you can send to faculty and curriculum committees. The manifest keeps the state of the course for the skills. The timeline at .idstack/timeline.jsonl records each run. /idstack:pipeline writes an index.md dashboard with readiness scores, the issues that recur across skills, and a link to each report.

Three ways to install.

Chrome Extension

In-Browser (Canvas / Docs)

Audit Canvas modules and assignments, Google Docs syllabi and web course pages in the Chrome side panel. No command line.

Install from Chrome Web Store Free

Claude Desktop App

No Terminal

In the Code tab of the Claude desktop app, select a folder for your course. Then paste this line in the message box:

› /plugin marketplace add savvides/idstack

Click +, then Add plugins, and install idstack. Then start a new session and select the course folder again, because Claude Code loads a plugin only when a session starts. Type /idstack:start. Each skill that writes a report gives you a link to open it in the app. In Cowork, open Customize, then Plugins, select Add marketplace and enter savvides/idstack.

Claude Code Plugin

All 16 Skills
$ git clone https://github.com/savvides/idstack.git && cd idstack && ./setup

./setup registers idstack with Claude Code and installs all 16 skills. Re-run it after a git pull to update.

You need a bash shell (Terminal on macOS or Linux, WSL or Git Bash on Windows). ./setup does not run in PowerShell or cmd. You also need Python 3.9 or later, because the skills save their results with it. scripts/idstack-doctor checks for it.

To check the install, run scripts/idstack-doctor. To see the health of a course, run scripts/idstack-status.

New to Claude Code? Install the Claude Code command-line tool first, then paste the command above in a terminal. In the Claude desktop app, use the steps in the Claude Desktop App card. When Claude Code starts, run /idstack:start.

Not using Claude Code or Cowork? The idstack skills run in Claude Code and Cowork. Use the Chrome extension, or fork the repo and adapt the skills for a different agent, for example Codex or Antigravity. idstack does not support or test those forks.
